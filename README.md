# Mariagram

A console-based Telegram client that fetches your chat data and gives you full freedom to use it however you like (analysis, backups, feeding it into other tools, etc).

## Table of contents
- [Setup](#setup)
- [Python files](#python-files)
- [Database schema](#databasemessage_logdb)

## Setup

```bash
cd <mariagram folder>
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```dotenv
API_ID=<your telegram api id>
API_HASH=<your telegram api hash>
SESSION_NAME=<any name>
```

Then run:

```bash
python gui.py
```

### Requirements
- Python 3.10+ (uses modern `asyncio` features)

### Optional: MongoDB
To persist full fetch data (not just the static log), install MongoDB and set its connection path in the `MongoServer` class in `mariagram_lib.py`. Without it, the program still works, but only the static data in `data/message_log.db` gets saved — dynamic fetch data won't persist.

## Python files

### `tonia.py`
Shared utility functions reused across several of the author's projects.

### `session_generator.py`
*Optional.* Lightweight script to generate a `.session` file. Can be skipped — `message_logger.py` does the same thing on its own.

### `page_writer.py`
Implements the pagination system used by `gui.py`. Needed because the console "forgets" earlier output once there's a lot of text.

### `message_logger.py`
Core fetching logic. Runs three independent fetch strategies, each toggleable via a config flag:

| Strategy | Flag | Behavior |
|---|---|---|
| Backfill | `backtrack` | Fetches messages from the last checkpoint up to now (catches up on anything missed while the program wasn't running) |
| Forward fill | `forward_scan` | Fetches older messages, working backward into chat history |
| Live handler | `runtime_check` | Streams new messages as they arrive in real time |

Set `print_messages = False` for normal use (recommended for performance); enable it only to debug/verify fetching.

### `mariagram_lib.py`
Shared library of classes and helpers used across the project.

### `gui.py`
Console GUI for the user, built on the pagination system from `page_writer.py`.

**States:**
- **Choose chat** — browse the list of available chats.
  - Scroll: `a` / `←` (left), `d` / `→` (right)
  - Jump to input mode: `esc`, `w`, or any digit `0–9` (then type the chat index)
- **Read chat** — read messages in the selected chat.
  - Scroll: `a` / `←` (left), `d` / `→` (right)
  - Back to chat selection: `esc` or `w`

### `media.py`
Downloads media for a given chat ID and message ID. This is a separate, manual step — not run automatically by `message_logger.py`, to keep normal fetching fast. **Cannot be run at the same time as `message_logger.py` or `gui.py`.**

### `<SESSION_NAME>.session`
> ⚠️ **Do not share this file.** It contains your Telegram login/authentication data — anyone with this file has full access to your Telegram account, including reading messages and sending them as you.

Generated by `session_generator.py`, `media.py`, `gui.py`, or `message_logger.py`.

## Database (`data/message_log.db`)

SQLite database containing the user's messages. Suitable as input for other projects (AI pipelines, sentiment analysis, search, etc).

**Tables:**

`chats` — chat metadata
```sql
CREATE TABLE IF NOT EXISTS chats (
    id TEXT PRIMARY KEY,
    name TEXT,
    number TEXT,
    username TEXT,
    type TEXT
)
```

`senders` — sender metadata
```sql
CREATE TABLE IF NOT EXISTS senders (
    id TEXT PRIMARY KEY,
    name TEXT,
    username TEXT,
    number TEXT
)
```

`messages` — individual messages
```sql
CREATE TABLE IF NOT EXISTS messages (
    id TEXT,
    chat_id TEXT,
    sender_id TEXT,
    time TIMESTAMP,
    time_in_zone TIMESTAMP,
    time_formatted TEXT,
    text TEXT,
    PRIMARY KEY (id, chat_id),
    FOREIGN KEY (chat_id) REFERENCES chats(id) ON DELETE CASCADE,
    FOREIGN KEY (sender_id) REFERENCES senders(id) ON DELETE CASCADE
)
```
